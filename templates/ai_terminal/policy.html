{# ======================================================== how it works #}

{% icon "shield-check" "h-4 w-4 text-emerald-600 dark:text-emerald-400" %} {% translate "How every command is judged" %}

  1. {% translate "Lexical check." %} {% translate "Text that only makes sense when reaching for a shell — chaining, piping, redirection, command substitution, newlines, null bytes — is refused before anything is parsed. Known break-out sequences such as remote downloads and script hosts are refused by name." %}
  2. {% translate "Executable allowlist." %} {% translate "The program name is normalised (a full path to an interpreter still resolves to its plain name) and must be one of the tools listed below. Anything else is refused outright — never “allowed with a warning”." %}
  3. {% translate "Sub-command rules." %} {% translate "Reading is safe; changing state needs approval; destroying data or publishing it is never permitted. The tables below list each case." %}
  4. {% translate "Workspace jail." %} {% translate "Every argument that looks like a path is resolved and must land inside the workspace. Parent traversal, symlinks, junctions, UNC network paths, drive-relative paths, short 8.3 names, reserved device names and NTFS alternate data streams are all refused. Secrets and the database file are protected even inside the workspace." %}
  5. {% translate "Human approval." %} {% translate "A command needing approval does nothing until a named person with the approval right allows it. Editing a command before approval re-runs the whole check — approval never buys a bypass." %}
  6. {% translate "Audit." %} {% translate "Proposals, approvals, rejections, refusals and executions are all written to the audit log with the person responsible." %}
